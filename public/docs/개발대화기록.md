# 🗣 개발 대화 기록 (백엔드 초기 구축 및 프론트엔드 연동)

이 문서는 AI와 사용자가 함께 진행한 **스프링 부트 백엔드 구축 및 리액트 연동 작업**의 전체 대화와 문제 해결 과정을 요약한 기록입니다. 나중에 어떤 흐름으로 개발이 진행되었는지 참고하기 위해 작성되었습니다.

---

## 1. 초기 요구사항 정의 및 백엔드 설계
*   **요구사항:** 기존 정적(Static)이었던 React 포트폴리오를 동적으로 바꾸기 위해 `myportfolio_back` 폴더에 Spring Boot + PostgreSQL 기반의 백엔드 구축 요청.
*   **핵심 변경 사항:** 초기에는 AWS S3에 이미지를 업로드하려 했으나, **로컬 서버(uploads 폴더)에 멀티파트(Multipart) 방식으로 저장**하는 것으로 방향을 수정함.
*   **결과:** `백엔드계획.md` 문서를 로컬 스토리지 업로드 방식으로 전면 수정함.

## 2. 백엔드(Spring Boot) 기본 코드 스캐폴딩
AI가 다음 핵심 클래스들을 모두 작성하여 프로젝트를 구성함.
*   **`Project.java` / `ProjectRepository.java`**: PostgreSQL 데이터베이스와 매핑되는 엔티티 및 저장소.
*   **`LocalFileUploader.java`**: `MultipartFile`을 받아 로컬 `uploads/` 폴더에 이미지를 저장하고 UUID 기반의 파일명을 반환하는 서비스.
*   **`WebConfig.java`**: 프론트엔드에서 `/images/**` 경로로 로컬 폴더의 이미지에 접근할 수 있도록 정적 리소스 핸들러 추가. CORS 전역 허용 설정.
*   **`ProjectController.java`**: `@RequestPart`를 이용해 JSON 데이터와 이미지 파일을 동시에 안전하게 받는 REST API 구성.
*   **`GlobalExceptionHandler.java`**: 파일 크기 초과(MaxUploadSizeExceededException) 등의 에러를 깔끔하게 처리하는 글로벌 예외 핸들러.

## 3. 환경 셋팅 및 트러블 슈팅 (문제 해결 과정)
사용자가 직접 로컬 서버를 띄워보는 과정에서 여러 문제들을 함께 해결함.

1.  **Java 버전 문제 (8 -> 17)**
    *   *문제:* 사용자의 PC에 Java 8이 설치되어 있어 Spring Boot 3.x 버전 빌드 실패.
    *   *해결:* `winget`을 통해 `Temurin 17 JDK`를 설치하고 환경변수를 업데이트하도록 안내함.
2.  **명령 프롬프트(CMD) 명령어 오류**
    *   *문제:* 윈도우 CMD에서 맥/리눅스용 명령어인 `./gradlew`를 쳐서 오류 발생.
    *   *해결:* 윈도우용 명령어인 `gradlew bootRun`으로 정정하여 안내.
3.  **데이터베이스 접속 및 생성 문제**
    *   *문제:* 백엔드 기동 시 `FATAL: database "myportfolio" does not exist` 에러 발생.
    *   *해결:* DBeaver(DB 클라이언트) 설정 화면에서 `postgres` DB로 먼저 접속한 뒤, VS Code의 SQL 편집기에서 `CREATE DATABASE myportfolio;` 쿼리를 실행하도록 도와주어 해결. (application.yml 비밀번호도 `1985`로 동기화 완료)

## 4. 프론트엔드(React) 연동 작업
백엔드가 정상 구동된 후, React 프론트엔드에서 API를 호출하도록 코드를 수정함.

1.  **Axios API 모듈 작성 (`projectApi.ts`)**
    *   `GET /api/projects`로 리스트를 불러오고, `POST /api/projects`로 `FormData`를 전송하는 로직 구성.
2.  **모달 UI 제작 (`ProjectUploadModal.tsx`)**
    *   이미지 파일, 영어/일본어 제목, 설명, 스택 등을 폼(Form)으로 입력받을 수 있는 깔끔한 UI 다이얼로그 추가.
3.  **데이터 바인딩 (`ProjectGrid.tsx`)**
    *   기존에 하드코딩 되어있던 가짜 데이터(Dummy Data)를 걷어내고, 서버에서 받아온 빈 배열을 `useEffect`로 그리도록 수정.
4.  **TypeScript `import type` 에러 (흰 화면 문제)**
    *   *문제:* `npm run dev` 실행 시 화면이 하얗게 뜨는 SyntaxError 발생.
    *   *해결:* Vite 번들러가 TS Interface(`ProjectDto`)를 컴파일할 때 겪는 충돌을 막기 위해 `import { type ProjectDto }`로 문법을 명시적으로 수정하여 해결함.

## 5. 결론 및 향후 계획
*   현재 프론트엔드와 백엔드가 완벽하게 연결되어 데이터베이스 기반으로 동작하는 상태가 됨.
*   더미 데이터는 모두 지워졌으며, 사용자가 직접 UI의 `[+ Add Project]` 버튼을 통해 실제 프로젝트 데이터를 넣어야 함.
*   다음날 새로운 컴퓨터 환경에서 똑같이 작업할 수 있도록 **`백엔드연동방법.md`** 가이드를 추가로 작성함.
