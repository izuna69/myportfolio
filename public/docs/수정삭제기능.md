# 프로젝트 수정 및 삭제 기능 가이드 (설계 문서)

현재 생성(Create)과 조회(Read)만 가능한 포트폴리오 프로젝트에 **수정(Update)과 삭제(Delete)** 기능을 추가하기 위한 전체 설계 문서입니다.

## 1. Backend (Spring Boot) 변경 사항

### 1-1. `Project.java` (Entity)
*   엔티티 내부에 필드 값을 변경할 수 있는 `update(...)` 비즈니스 로직 메서드를 추가하여 외부에서 안전하게 데이터를 바꿀 수 있도록 합니다.

### 1-2. `LocalFileUploader.java` (Service)
*   `deleteFile(String fileUrl)`: DB에서 프로젝트가 삭제되거나, 이미지가 교체될 때 기존 용량을 차지하고 있던 로컬 이미지 파일을 찾아 **물리적으로 삭제**하는 메서드를 추가합니다.

### 1-3. `ProjectService.java`
*   `updateProject(Long id, ProjectRequestDto requestDto, MultipartFile newImage)`: 
    1. DB에서 해당 ID의 프로젝트를 찾습니다.
    2. 만약 폼에서 새로운 이미지가 업로드되었다면, 기존 이미지를 물리적으로 삭제하고 새 이미지를 저장한 뒤 URL을 업데이트합니다.
    3. `requestDto`로 들어온 텍스트 정보들을 `update` 메서드를 통해 반영합니다.
*   `deleteProject(Long id)`: 
    1. 프로젝트 정보를 삭제하기 전에, 저장되어 있던 이미지 경로를 확인해 물리 파일을 삭제합니다.
    2. DB에서 프로젝트 엔티티를 삭제합니다.

### 1-4. `ProjectController.java`
*   `@PutMapping("/{id}")`: `multipart/form-data`로 들어오는 수정 요청을 처리합니다. 이때 이미지는 필수가 아닙니다.
*   `@DeleteMapping("/{id}")`: 특정 프로젝트를 삭제하는 REST API 엔드포인트를 노출합니다.

---

## 2. Frontend (React) 변경 사항

### 2-1. `projectApi.ts`
*   `updateProject`: Axios를 사용해 백엔드의 PUT 엔드포인트를 호출합니다.
*   `deleteProject`: Axios를 사용해 백엔드의 DELETE 엔드포인트를 호출합니다.

### 2-2. `ProjectUploadModal.tsx`
*   이름은 UploadModal이지만 **'생성'과 '수정'을 겸용**하도록 바꿉니다.
*   프롭(prop)으로 `initialData`를 전달받으면 'Edit Mode'로 동작하여 기존 글 내용이 Input 칸에 미리 채워집니다.
*   수정 모드일 때는 썸네일 이미지를 변경하지 않고 텍스트만 바꿀 수 있어야 하므로, 파일 입력(Input file)의 `required` 속성을 조건부로 해제합니다.

### 2-3. `ProjectCard.tsx`
*   디자인을 해치지 않는 선에서 프로젝트 카드 내부 (보통 우측 상단 또는 하단)에 **Edit(수정)** 버튼과 **Delete(삭제)** 아이콘을 배치합니다.
*   삭제 시 즉시 삭제되지 않고 `window.confirm` 알림창을 띄워 사용자에게 한번 더 확인을 받습니다.

### 2-4. `ProjectGrid.tsx`
*   자식 컴포넌트인 `ProjectCard`에게 `onEdit`, `onDelete` 함수를 내려줍니다.
*   `onEdit` 호출 시 수정 모달을 띄울 프로젝트의 데이터를 상태(state)에 저장하고 모달을 엽니다.
*   수정이나 삭제가 완료되면 `fetchProjects()`를 다시 호출하여 바뀐 화면을 새로고침합니다.
